# 业务验收

`make verify` 包含静态检查、构建、原型 JavaScript 与部署脚本语法检查，以及 `lifecycle.py` 的四组生命周期回归：正常退出、启动失败、后台任务失败及外部资源所有权。生命周期检查不连接数据库或模型。

在项目根目录执行：

```sh
BANKPILOT_ACCEPTANCE_ADMIN_URL=postgresql://localhost/postgres make verify-business
```

连接必须显式提供，主机只接受本机回环地址，数据库角色需有创建数据库权限。脚本自行创建随机命名的 `bankpilot_acceptance_*` 数据库，执行迁移、合成样本和 HTTP 断言，结束后删除自己创建的库；不向连接参数指定的现有库写业务数据。缺少连接配置时失败退出，不跳过验收。认证或迁移失败同样返回非零。

`business.py` 覆盖独立金额预期、跨月退款及原消费改类、重复/转账排除、无预算/零数据/负净支出、多币种、用户隔离、稳定分页、两种工具入口、结构化追问、账本及规则版本失效、可重复读并发、预算提案并发确认、撤销导入和容量边界。固定模型决策只验证程序契约，不代表真实模型质量。

可连续运行两次检查样本独立性。CI 使用独立 PostgreSQL 服务执行同一入口。真实模型和浏览器验收需单独记录，真实账单及凭据不得加入此目录。

前端请求竞争回归：`make verify-interactions`。脚本使用现有 TypeScript 编译器及最小 Hook 调度器，验证迟到响应、隐藏后重读、分页旧数据隐藏、冲突提示和本地变更事件；它不替代真实 React DOM、焦点和浏览器布局验收。

真实模型场景：在提供相同管理员连接变量后执行 `make verify-model`，模型配置读取项目环境配置。脚本创建独立合成库，发送 20 个查询/追问/能力边界场景，并输出逐例结果；会调用已配置模型供应商。自动门槛检查工具范围与无写提案，输出文字需另行复核，不能将结构检查通过率等同于文字质量。


## R2

`make verify-conversations` 使用与 business.py 相同的本机随机库保护，覆盖请求受理/去重、
中断与迟到完成、提案原子性、用户隔离、容量、分页、上下文上限、历史版本降级、
恢复清理、真实 pg_dump/pg_restore 与迁移往返。无需模型配置，不产生外部调用。
`make verify-interactions` 另运行 conversations-frontend.cjs 的四组恢复与响应竞争检查。
真实模型脚本已更新至协议 2；这次未运行，不以固定输出证明自然语言指代理解质量。

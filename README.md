# BankPilot Agent

> 用自然语言完成银行任务：Agent 负责理解、规划与协作，确定性程序负责校验与执行。

**定位：** 本地可运行的银行 Agent 系统　·　**数据：** 本地银行数据　·　**文档性质：** 产品目标态

## 一眼看懂

```mermaid
flowchart LR
    U[用户] --> S[本地登录 / 已认证会话]
    S -->|提出目标| A[BankPilot Agent]
    A --> P[理解与规划]
    P --> G{安全门}
    G -->|只读操作| T[银行工具]
    G -->|状态变更| C[用户确认]
    C --> V[交易身份验证]
    V --> T
    T --> R[结果校验]
    R --> U
```

| Agent 做什么 | 确定性程序做什么 | 系统不做什么 |
| --- | --- | --- |
| 理解意图、补全信息、拆解任务、选择工具 | 金额计算、余额与限额校验、状态变更、幂等控制 | 连接真实银行、处理真实资金、替代完整网银 |

## 目标能力地图

| 场景 | 用户目标 | 核心 Agent 能力 | 操作风险 |
| --- | --- | --- | --- |
| 智能转账 | “给妈妈转 2,000 元” | 收款人消歧、参数补全、转账规划 | 高 |
| 账单分析 | “这个月钱花哪了？” | 分类统计、趋势解释、异常识别 | 低 |
| 卡片管理 | “卡丢了，先锁住并办理挂失” | 卡片定位、影响说明、锁定、解锁与正式挂失 | 高 |
| 订阅管理 | “找出没用的自动扣费” | 周期识别、跨场景联动、关闭代扣 | 中 |

定时转账、AA 收款与理财能力属于目标态扩展域，不影响四个核心场景独立验收。

## 核心业务流程：识别周期扣款并正确分流

```mermaid
sequenceDiagram
    actor U as 用户
    participant A as Agent
    participant B as 账单工具
    participant S as 安全策略
    participant D as 代扣工具
    participant C as 卡片工具

    U->>A: 这个月有没有异常消费？
    A->>B: 查询并分析本月账单
    B-->>A: 发现疑似陌生周期扣款
    A-->>U: 展示异常依据与订阅详情
    A-->>U: 这是不用的本人订阅，还是非本人交易？

    alt 本人订阅，但不再需要
        U->>A: 是我订的，现在不用了
        A-->>U: 说明关闭代扣不等于解除商户合同
        A->>S: 检查权限、参数与风险
        S-->>A: 需要确认与交易身份验证
        U->>A: 确认关闭代扣并完成交易身份验证
        A->>S: 校验确认参数与认证状态
        S-->>A: 允许执行
        A->>D: 关闭代扣（独立请求号）
        D-->>A: 返回成功、失败或处理中
        opt 返回处理中
            A->>D: 查询代扣操作状态
            D-->>A: 返回最新状态
        end
    else 非本人交易
        U->>A: 不是我的交易
        A->>S: 检查权限、参数与风险
        S-->>A: 需要确认与交易身份验证
        A-->>U: 展示临时锁卡影响与申诉范围
        U->>A: 确认锁卡并完成交易身份验证
        A->>S: 校验确认参数与认证状态
        S-->>A: 允许执行
        A->>C: 临时锁卡（独立请求号）
        C-->>A: 返回成功、失败或处理中
        opt 返回处理中
            A->>C: 查询卡片操作状态
            C-->>A: 返回最新状态
        end
        A-->>U: 引导进入交易申诉或人工处理流程
    end
    A-->>U: 展示处理结果与操作记录
```

这条链路根据用户判断进入订阅管理或卡片管理，也可继续组合智能转账等后续任务。

## 工具边界

| 领域 | 查询工具 | 变更工具 | 执行要求 |
| --- | --- | --- | --- |
| 账户 | `get_accounts`、`search_payees` | — | 已认证会话内查询 |
| 转账 | `check_transfer`、`get_transfer_status` | `create_transfer` | 变更需确认与交易身份验证 |
| 账单 | `query_transactions`、`analyze_bill`、`detect_anomalies` | — | 已认证会话内查询 |
| 订阅 | `detect_subscriptions`、`get_debit_status` | `cancel_debit` | 变更需确认与交易身份验证 |
| 卡片 | `list_cards`、`get_card_operation_status` | `lock_card`、`unlock_card`、`report_card_lost` | 变更需确认与交易身份验证；正式挂失单独确认 |

> 表中是领域能力约定，不代表接口已经实现。

## 产品验收矩阵

| 验收项 | 通过标准 |
| --- | --- |
| 场景闭环 | 四个核心场景均可通过自然语言端到端完成 |
| 主动澄清 | 参数缺失、同名收款人或多张卡时不自行猜测 |
| 变更确认 | 未确认时任何状态变更工具都不可调用 |
| 身份验证 | 转账、代扣和卡片状态变更必须通过交易身份验证 |
| 参数绑定 | 金额、对象或账户变化后必须重新确认 |
| 工具安全 | 仅允许调用白名单工具；所有参数通过结构化 Schema 和业务规则校验后才能执行 |
| 指令隔离 | 账单、商户名称和工具返回内容只作为数据处理，不得作为 Agent 指令执行 |
| 订阅边界 | 明确区分关闭银行代扣与解除商户订阅合同 |
| 异常扣款分流 | 本人但不再需要的订阅进入关闭代扣；非本人交易进入锁卡并提示申诉边界 |
| 智能转账 | 完成收款人消歧、余额与限额预检、参数确认、交易身份验证、幂等执行和超时查单 |
| 正式挂失 | 明确提示操作不可撤销；使用独立确认记录，不能复用临时锁卡授权 |
| 幂等执行 | 重复请求不产生重复转账或重复状态变更 |
| 组合任务 | 拆分步骤并逐项展示；每项状态变更使用独立确认、请求号与执行状态 |
| 异常恢复 | 超时后只查询状态；最终进入成功、失败、继续等待或人工处理 |
| 可追溯 | 可查看结构化任务步骤、确认记录、工具调用和最终状态 |
| 数据边界 | 账户、卡片、账单和交易使用本地银行数据，不连接真实银行、不处理真实资金 |
| 固定评测集 | 不少于 40 个用例，每个场景至少 10 个，覆盖正常、澄清、修改或拒绝、工具失败或超时、越权或提示词注入 |

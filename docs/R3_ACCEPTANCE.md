## 实现

- 统一确定性查找服务：用户/日期/账户/币种/方向/金额/批次先在 SQL 限定，最多读取 10,001 笔判定容量。完整候选内执行 NFKC、casefold、空白规范化、字面子串与最终分类匹配；稳定排序，每页 20 笔。10,000 笔可查询，超过容量明确拒绝。
- 搜索、完整 CSV、按 ID 详情使用认证前建立的可重复读快照；分页和导出核验账本修订号及 `search-v1`。CSV 先完整构造，错误不会变成部分成功文件。原列表契约增加可空修订号，旧快照仍可读。
- 分类写入必须提供修订号，用户锁内直接读取当前修订标量，防止认证 ORM 缓存绕过校验；所有 Web 调用方同步升级。旧核查快照缺少修订号时不能直接编辑，需重新核查。
- 账本区分草稿与执行条件，支持 URL hash 恢复、条件标签、分页、按 ID 详情、导出全部匹配结果。错误保留输入，旧结果仍显示旧条件；退出清理 URL，迟到搜索/详情响应受请求序号约束。
- 异常核查按需加载：在完整期间计算规则，再选择与当前页有关的项，返回完整关联证据；条目与证据均支持独立分页。核查容量失败不影响查找，保存判断检查旧修订。
- 助手新增只读 `find_transactions`，共用搜索服务。模型只收到条件、数量和状态，逐笔内容由接口直达前端。同名账户直接返回确定性候选澄清，不执行放宽查询。
- 会话协议升级为 3，结果结构版本为 2，原结果结构版本 1 继续读取。查找条件独立保存，与消费范围共用上下文并发版本；受理时冻结条件，模型迟到完成不能覆盖后来选择。手动结果不产生助手轮次，原历史首屏保留；条件保存失败阻止以未保存范围续问，响应丢失先读回核对。
- 迁移 `20260921_0014` 新增会话/轮次查找条件和会话上下文版本。删除及恢复准备清理查询文本；恢复准备重复执行保持幂等。备份结构版本同步升级。

## 查询测量

本机 PostgreSQL、ASGI HTTP 调用、合成交易。每个并发档 4 轮，单请求共 4 样本、并发 5 共 20 样本；第一页与后续页混合。P95 采用排序位置统计，样本规模较小，不能作为生产容量承诺。响应约 9.8KB。

| 候选数 | 首次查询 ms | 并发 | 热查询 P50 ms | P95 ms |
| --- | --- | --- | --- | --- |
| 1,000 | 25.04 | 1 | 20.05 | 20.55 |
| 1,000 | 25.04 | 5 | 81.39 | 126.33 |
| 10,000 | 200.61 | 1 | 196.12 | 199.37 |
| 10,000 | 200.61 | 5 | 900.88 | 966.66 |

单请求达到设计中本机 P95 ≤ 500ms 的暂定目标。并发下 CPU 分类/规范化仍有成本，没有增加容量或截断匹配集。账户+日期代表查询的 EXPLAIN 使用现有 `ix_transactions_account_booking` 与增量排序；该记录不是所有连接查询或远程数据库的完整计划验收。未新增索引。

## 边界与发布条件

- 真实模型没有调用、没有产生外部费用。当时准备了 22 个场景，明确条件、歧义、不支持请求和英文均在内；场景文件已于 2026-09-21 随测试删除，自然语言条件提取质量未认证。
- 使用合成数据，不能证明真实微信/支付宝样本兼容。弱网、真机、生产代理及远程链路压力未验收。
- 浏览器没有穷举所有故障和多标签组合；确定性回归覆盖跨会话迟到、保存响应丢失、上下文冲突、受理快照及模型迟到完成。
- 不支持模糊匹配、别名、任意 SQL、无限跨年查询或新增金融写操作。
- 发布需另行授权：前后端同批升级、备份及业务库迁移、线上验收。旧协议请求和缺修订号写入会被拒绝，不能只部署一端。

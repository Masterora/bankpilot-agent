# 飞书与支付宝沙箱

系统支持飞书企业自建应用机器人和支付宝电脑网站支付沙箱。默认关闭，配置完成后在「设置」使用；不会自动启用、发送消息或执行支付。配置说明和验收边界见下文，验收步骤见[验收说明](ACCEPTANCE.md)。

## 配置

根目录与 `deploy/.env.example` 已包含以下变量。凭据由运行环境注入，不填到前端、不提交仓库，也不要粘贴到对话中。私钥接受带 PEM 标记的内容或裸 PKCS#1 内容；PEM 中的换行可以写成字面量 `\n`。PKCS#8 请保留 `BEGIN PRIVATE KEY` 标记。

| 变量 | 用途 |
| --- | --- |
| `BANKPILOT_PUBLIC_URL` | 无路径、查询或片段的 HTTPS 站点源，例如 `https://bankpilot.example.com` |
| `FEISHU_ENABLED` | 显式启用飞书，默认 `false` |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 企业自建应用凭据 |
| `FEISHU_ENCRYPT_KEY` / `FEISHU_VERIFICATION_TOKEN` | 事件加密与验证配置，两个都必填 |
| `FEISHU_TENANT_KEY` | 允许访问的企业 tenant key，禁止跨企业事件 |
| `ALIPAY_SANDBOX_ENABLED` | 显式启用支付宝沙箱，默认 `false` |
| `ALIPAY_SANDBOX_APP_ID` / `ALIPAY_SANDBOX_SELLER_ID` | 沙箱应用 ID、对应卖家账号 UID |
| `ALIPAY_SANDBOX_PRIVATE_KEY` / `ALIPAY_SANDBOX_PUBLIC_KEY` | 应用私钥、支付宝沙箱公钥，RSA2，至少 2048 位；公钥不是应用公钥 |

启用任一渠道必须提供完整配置和 HTTPS 源；支付宝 RSA 密钥启动时解析验证。Compose 已透传这些变量，但没有改变当前 Tailscale 入口或发布网络。平台无法访问 Tailscale 私网回调，需要另行配置可公网访问的 HTTPS 反向代理，保留原始请求体与请求头，并转发以下两个回调路径。公开站点应配置 `BANKPILOT_SESSION_COOKIE_SECURE=true`。不应为此暴露数据库。共享环境迁移、网络变更和部署需要另行授权。

## 飞书设置与使用

1. 在飞书开放平台创建企业自建应用，启用机器人，限定可用人员。申请读取用户发送给机器人的单聊消息权限和以应用身份发消息权限；常见权限码为 `im:message.p2p_msg:readonly`、`im:message:send_as_bot`，以控制台当前显示为准。不需要群消息或通讯录敏感权限。
2. 选择 HTTP 事件订阅，配置 Encrypt Key、Verification Token；订阅 `im.message.receive_v1`。事件地址为 `https://你的域名/api/v1/integrations/feishu/events`。支持加密的 URL challenge；本实现要求加密事件，不接受明文降级。
3. 发布测试版本或正式应用，使目标用户可以私聊机器人。填入运行环境配置并重启服务。
4. 登录 BankPilot「设置 → 飞书」，获取绑定码，在机器人私聊中发送 `绑定 绑定码`，然后刷新网页状态。绑定码有效 5 分钟、仅使用一次，重新生成会使旧码失效。禁止把绑定码发到群里。
5. 私聊询问「本月预算还剩多少」「餐饮支出」，或发送「帮助」。每条消息是独立查询，以业务时区当前月为参考，明确月份仍可由助手工具查询；多轮上下文和证据明细在网页助手历史使用。预算提案只在网页确认；文字“确认”不会写入预算。
6. 「解除绑定」会清理待发送消息并撤销渠道授权；修改本站密码也会在同一事务内解除绑定。切换应用或企业后须重新绑定。一个飞书身份不能在未解绑时切换至另一个本站账户。

机器人只处理允许企业内、已绑定用户发送的单聊文本，忽略群聊、机器人消息、非文本和未绑定身份。事件同时按 event ID 和 message ID 唯一去重；先持久化、后快速确认，消费者以数据库租约和领取令牌工作，最多尝试 3 次；已生成答复先持久化，再使用稳定 UUID 投递，失败重领不会再次调用模型。飞书提供的去重窗口仍以平台契约为准，不声称跨平台绝对 exactly-once。

助手沿用现有模型限额、只读工具与预算提案权限；开启渠道后，用户主动发来的普通问题可能产生现有模型费用，绑定与帮助不调用模型。本地验收使用确定性替身，未调用真实模型。队列全局最多 1,000 条，每用户每分钟最多受理 10 条、全局 120 条。达到上限返回可重试错误。

消息发送成功、取消或重试用尽后清理问题与回复正文；终态去重记录在后续消费扫描时保留 7 天。正常助手问题还会出现在本站历史，沿用原有历史上限与删除行为。个人导出包含本人沙箱订单、消息记录和助手历史，排除飞书授权表与绑定码哈希。注销账户通过外键级联清理这些记录。

## 支付宝沙箱设置与使用

1. 在支付宝开放平台沙箱创建应用，检查当前沙箱支持的产品，配置 RSA2 应用公钥，取得对应的支付宝沙箱公钥和卖家 UID。本实现使用 `alipay.trade.page.pay` 与 `alipay.trade.query`，需要沙箱支持电脑网站支付产品。
2. 填入沙箱环境变量，启用后重启。异步通知地址由服务端固定拼接为 `https://你的域名/api/v1/integrations/alipay/notify`，不接受客户端指定。
3. 在「设置 → 支付宝沙箱」输入说明和人民币金额，勾选含当前金额的确认项，再点击创建。单笔范围为 0.01～10,000.00 元，最多两位小数，服务端使用 Decimal 验证。
4. 点击「前往沙箱付款」，使用支付宝提供的沙箱买家账号和沙箱客户端完成付款。订单有效 15 分钟；请求与到期时间显式使用北京时间，不依赖服务器时区。浏览器刷新后可用「查询支付状态」恢复仍有效的付款链接。付款页跳转不代表支付成功。
5. 支付结果以 RSA2 验签通知或官方 SDK 验签查单为准。通知核对应用、卖家、商户订单号、交易号和精确金额，拒绝重复表单字段。重复通知幂等；已付款不退回待支付，但合法全额退款可以转为关闭。关闭和交易完成都是终态，迟到的成功通知或旧查单结果不能重新打开关闭订单。查单每用户每分钟最多 10 次、全局 120 次；并发每用户 2 个、全局 8 个。

支付网关硬编码为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，没有生产网关配置项。前端也复查付款链接的源和路径。订单归属本站用户；其他用户不能列出或查询。创建请求按用户和操作键幂等，参数改变拒绝复用旧键。没有自动付款、转账、退款、代扣、真实银行账户操作或个人支付宝历史账单读取。沙箱结果不创建账本流水、不改变账本修订号。

## 升级和恢复

新增 `20261016_0024`，创建 `feishu_bindings`、`feishu_messages`、`alipay_sandbox_orders` 三表，当前共 39 表。先备份并按运行手册执行迁移，再同批更新 API/Web。降级会删除绑定、消息和沙箱订单记录，不改变原账本；有数据的共享环境不得直接降级。

备份包含三表，环境密钥不在数据库中。恢复后的离线准备会删除飞书绑定和消息队列，避免旧授权复活或重发；必须由用户重新绑定。保留沙箱订单历史，不自动发起付款或主动查询。

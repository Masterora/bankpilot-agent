# 当前能力与验证边界

BankPilot 以用户导入的账单为依据，提供整理、关系核对与只读 Agent 分析。账单来源是否完整、是否符合某个平台的全部导出格式，需要独立验证。

## 已实现能力

注册与会话、账户绑定、CSV / XLSX 识别预览、批量导入、重复处理、分类修正、导出与批次撤销构成账本流程。交易保留来源批次和原始行号，用户可以从结果追溯到导入记录。

关系工作区支持重复、本人转账和退款的候选、确认、排除与撤销。只有确认关系影响调整统计；原始流水继续保留。调整金额按币种和交易日期计算，退款按到账日冲减流出。

Agent 将自然语言转换为日期查询，由本地领域服务计算原始统计、关系调整和证据。运行结果保存读取时的快照，之后确认关系或撤销导入不会重算已保存的运行结果。没有关系快照的运行记录只展示其原有结果。

Agent 查询仅支持所选日期内的全部账单。规划规则要求拒绝账户、商户、金额、分类、平台或仅退款等附加筛选，避免丢弃条件后返回全量结果；独立账本页面继续提供已有筛选。

React 工作区提供总览、账户与导入、账本、关系核对、Agent 核查、月度报告、周期扣款、预算与审计九个入口。总览读取真实关系汇总，按币种展示原始与调整收支；总览、账本和关系核对共享期间。深色布局、中英切换与移动导航对应静态 [产品页面](final-product.html)。

月度报告、周期扣款和预算业务尚未实现，入口明确显示未开放，不使用静态假数据代替业务结果。静态页面中的交互不代表对应服务已上线。

## 验证如何判定

静态检查与 Web 构建验证代码约束；数据库迁移验证结构可升级；接口和浏览器验收验证实际操作。三类证据不能互相替代，也不能据此宣称所有场景已经覆盖。

关系快照的验收重点是：原始与调整口径一致、跨期双方证据齐全、候选不改变金额、重读快照不漂移，以及并发修改和跨用户访问不混入结果。验证记录应说明使用的环境和实际场景。

CI 执行静态检查、构建和隔离数据库迁移，不包含完整业务回归。提交成功、CI 成功与线上可用分别判断。

静态检查与 Web 构建已通过。独立 PostgreSQL 验收覆盖迁移升降级、认证、导入去重、重复与转账确认、跨期退款、版本冲突、跨用户隔离，以及撤销导入后历史快照保持不变；测试数据与临时库均独立于业务库。

并发验收在关系读取和期间交易读取之间提交关系确认与分类修改：当前快照保持同一读取状态，下一次查询呈现最新结果，双方证据完整。

浏览器延迟响应验收覆盖旧分类修正成功与失败，均不覆盖新运行或阻断完成流程。模型响应边界通过 34 类畸形响应验证；真实 OpenRouter 的日期查询与六类附加筛选请求分别进入执行和拒绝路径。语义分类仍由模型完成，这些用例不代表对任意自然语言的完整保证。

真实 Chrome 验收覆盖上传、预览、导入、跨期手动关联、OpenRouter 查询与 SSE 完成、证据展开、中英切换、审计和保留模块入口。桌面与 390px 窄屏均已检查。真实来源文件认证和线上发布验收仍未完成。

React 九个入口已完成独立 PostgreSQL 与真实 OpenRouter 联调：注册登录、文件预览与导入、重复导入、无效行原子拒绝、账户改名、分类保存、关系确认、并发版本冲突、跨期退款、多币种统计、SSE 续读、筛选导出和历史快照均通过。中英切换与 320px / 390px 布局通过浏览器检查；总览失败重试另以受控响应验证。

文件解析的 36 项边界与合成来源用例覆盖编码、单表 XLSX、公式和多表拒绝、金额精度、行数限制，以及微信和支付宝的收支、退款与排除状态。合成用例不替代真实导出文件认证。验收使用独立测试库，不写入共享业务账本；测试数据在验收后清理。

## 使用边界

导航恢复与候选超限降级经过定向回归：受控数据库响应验证跨期证据、准确汇总与期间自身超限拒绝；受控 API 的真实浏览器验证刷新、前进后退及无效日期回退。该定向回归不等同于新增分支的真实数据库容量测试。

微信与支付宝适配仍需真实脱敏导出文件认证。合成文件只能验证解析规则，不能证明真实导出入口、历史格式和所有交易状态均受支持。

Agent 的查询范围、交易数与批次数描述本次读取的数据，不能证明完整账期。无交易也不等于没有消费。候选数量达到上限会明确提示。
候选扩展查询超过 10,000 笔时暂停候选发现，但保留期间统计与已保存关系证据；仅期间流水自身超过上限才要求缩小日期范围。页面及期间支持通过 URL 恢复。

拆分转账、汇兑和手续费差额尚不支持自动配对。系统不执行银行操作、不读取实时余额，也不代替银行确认退款或争议。

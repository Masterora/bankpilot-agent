# R6 发现决策切片交付与验证

日期：2026-09-29。代码已在本地实现，尚未推送或部署；共享业务库已迁移至 `20260929_0016`。服务端发现开关保持默认关闭。

## 本轮实现

- 新增 `20260929_0016` 迁移：按用户和组键保存发现决定，按用户和操作 ID 保存冻结回执；商户规范化版本单独固定为 `merchant-normalization-v1`。
- 服务端提供忽略、恢复、关联已有计划、解除关联；读取历史决定及单组证据核对。首次操作重读完整发现快照，关联校验目标计划归属和候选最近观测月份的账户、币种、规范化商户配置；恢复与解除不依赖当前流水容量。
- 当前发现默认只显示 `active` 组，翻页令牌覆盖全部决定。已保存决定列表只读、不扫描流水，未核对证据显示 `not_checked`。写入先锁用户，决定与回执同事务提交；相同操作 ID/载荷回放冻结回执，异载荷冲突。
- 固定支出页增加当前、已忽略、已关联视图及四种操作。发送前在用户隔离的 `sessionStorage` 保存原请求；结果不明时只允许按原操作 ID 与载荷重试。

本轮不创建计划，不改写 `recurring_matches`、账本金额或模型工具。候选识别精度未经真实样本认证。

## 已执行的本地检查

- `make verify`：Ruff、Mypy、ESLint、TypeScript、Vite 均通过；`git diff --check` 通过。前端浏览器矩阵不由这些静态检查证明。
- 独立 PostgreSQL 17.11：空库升级到 `20260929_0016`、`alembic check`、降级到 `20260922_0015`、再次升级及检查通过。最终结构的 `normalized_merchant` 为 `TEXT`，迁移与 ORM 一致。
- 合成账本直接调用业务服务：三个月候选，忽略→恢复→关联→解除关联版本为 1→4；同 key 同载荷回放、异载荷冲突、双用户隔离、两个不同操作 ID 并发仅一项成功、旧发现分页令牌拒绝、旧商户规范化版本拒绝。决策操作没有新增逐期匹配。
- 同一隔离库额外加入 10,001 笔窗口内流水：发现与单组证据核对返回容量错误，已保存决定仍可读取并撤销。撤销写入后强制回滚，原决定版本和操作回执数保持不变；原请求随后可成功提交。
- 真实 ASGI 路由与隔离数据库：关闭开关时可用性为 `enabled=false`，当前发现、历史决定、证据核对和写入均返回 404；受控开启后可用性与空列表读取成功。路由认证在此检查中由测试身份替代，不代表真实登录闭环。
- 本地 Web 连接真实 API 与隔离 PostgreSQL：测试账户完成真实登录、当前候选→忽略→已忽略证据核对→刷新后恢复→关联→已关联→解除的中文浏览器流程。375px 与 1440px 视口均无横向溢出；375px 和 1440px 截图检查了抽屉布局。先发现同账户同币种但商户不匹配仍可关联，已补充规范化商户校验；修复后合成服务用例拒绝错误计划，真实浏览器完成匹配商户的合法关联。
- 在同一隔离集群进行 `pg_dump`/`pg_restore` 到新数据库；还原后结构版本、1 条决定、5 条操作回执与 `database_evidence` 一致，原操作回放仍返回冻结的版本 1 回执。

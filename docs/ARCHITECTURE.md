# 系统架构

BankPilot 将账本事实、关系判断和分析结果分开保存。金额与权限由确定性代码控制，模型负责选择受限的查询步骤。

![BankPilot 系统架构](assets/architecture.svg)

## 模块职责

React 负责导入、账本、关系核对与 Agent 界面。FastAPI 验证会话和请求，应用服务组织事务；领域层实现来源解析、分类、交易关系与统计。PostgreSQL 保存用户数据和运行结果，Model Gateway 隔离 OpenRouter 接入。

来源适配器变化不应改变标准交易规则，模型供应商变化不应改变权限和金额口径。工作流通过端口访问领域能力，不直接编排数据库查询。

应用入口统一注入模型与核查端口，运行处理器不创建具体核查适配器。页面及查询期间保存在 URL 中，支持刷新恢复和浏览器前进后退；文件正文只保存在内存；待确认导入的配置、摘要与操作键保存在当前标签页 sessionStorage，用于刷新恢复。

## 从文件到证据

预览和导入复用解析契约。用户确认账户后，服务端重新校验并原子写入批次与交易。原文件在内存中处理，持久化交易保留批次和行号；分类修正和关系确认不覆盖原始金额。

Agent 在模型规划完成后读取用户账本。独立的核查端口在同一个数据库快照中装配期间交易、关系和证据，避免并发编辑使统计与证据来自不同状态。工作流使用该结果生成原始分析与调整分析，并将结果持久化。

重复打开运行记录读取已保存结果。该快照保留当时证据，不是当前账本的实时视图，也不等同于完整账本版本历史。

## 金额口径

重复关系由用户指定保留流水，只排除副本；本人转账排除已确认的双边收支；退款在到账日冲减流出。跨期的另一端作为证据保留，不移入本期统计。退款可能使本期调整流出为负。

候选限制为同币种：重复记录跨批次、等额且相差不超过一天；本人转账跨账户、等额反向且相差不超过三天；退款发生于支出后九十天内，累计不得超过原支出。服务端对人工配对同样复查事实、归属与并发版本。

原始统计与调整统计分别展示。分类汇总和异常规则基于原始交易，不应被标记为调整后的分类结果。

## Agent 边界

日期核查规划器仅接收用户任务及规划上下文，交易证据由本地服务装配。模型不能选择用户身份、修改交易、确认关系或绕过工具白名单；模型不可用不影响独立的导入与账本功能。

查询契约只接受日期范围，规划器对无法表达的附加筛选返回不支持。供应商响应的外层结构、计划和元数据均经校验，畸形响应统一返回模型输出无效。Web 按运行 ID 与修正请求序号接收异步结果，旧任务响应不能覆盖新运行。

快照包含原始交易、调整统计、规则与关系版本、双方证据和生成时间。覆盖信息只记录查询区间与读取数量，完整性保持未认证。候选截断单独标识，不能将部分数据包装为完整结果。

候选扩展窗口超过 10,000 笔时停止候选发现，另行完整读取期间流水和已保存关系的双边证据，继续提供确定性统计并标记候选未穷尽。只有期间流水自身超过 10,000 笔才要求缩小期间；任何截断集合均不得用于金额汇总。

## 代码组织

```text
web/src/app          页面注册、导航和跨页面期间
web/src/features     功能界面及各功能自己的状态 Hook
web/src/styles       基础、应用外壳、业务功能和响应式样式

api/.../api          按认证、账户、导入、交易、运行和报告拆分的 HTTP 路由
api/.../services     事务与用例编排
api/.../agent        模型规划、工具执行、结果组织
api/.../domain       解析、分类、金额与关系规则
api/.../adapters     领域端口与外部服务实现
api/.../db           按聚合拆分的仓储、ORM 模型与账本修订号
```

会话提供用户身份，业务查询强制用户隔离；密钥通过环境配置；数据库结构由 Alembic 管理；CI 使用独立数据库。周期扣款与预算使用独立规划服务，不参与月报任务调度；对话助手复用规划服务读取数据和确认预算修改。

## 月报快照与持久任务

月报复用 `ReviewGateway`，按月直接读取，不经过模型或 Agent 状态机。端口在同一个可重复读事务中先读取账本修订号，再读取流水、关系与证据；领域报告构建器复用原始统计规则。列表和状态查询不加载完整快照。

总览和关系工作区读取在认证前开启可重复读事务，认证与查询共享连接，不以用户写锁保护只读快照。总览 SQL 按期间过滤关系后聚合，只返回币种汇总和最近五条流水。

应用账本写入在同一事务内递增用户修订号。拒绝导入、没有新增流水的重复导入、重复保存相同分类、撤销无流水的批次不会递增。相关写入统一先锁用户，再锁源交易。跨月份共享用户修订号，因此提示表示账本发生变化，不断言本月金额变化。

持久报告记录合并一次生成任务与最终快照。提交按用户和幂等键唯一；领取使用 `FOR UPDATE SKIP LOCKED`，租约及领取令牌防止旧实例提交。删除使令牌失效并清除证据；用户级联清除也删除对应报告。首版仅支持手动触发，没有周期调度。

## 服务与页面边界

账户、月报和核查路由只处理 HTTP 契约、调用和提交结果；SQL 由对应仓储执行。核查服务负责重算证据、读取判断、锁定后重新验证，仓储不代替用例校验，也不隐式提交。总览是数据库只读投影，放在 `db/overview_repository.py`，直接返回 `OverviewSnapshot`；不再保留同名服务转发层。

核查列表使用 `ReviewList` / `ReviewItem`，运行历史使用 `RunHistory` / `RunHistoryItem` 明确响应字段。数据库中的可变 JSON 证据仍按原设计存储，不为了去掉 `Any` 而伪造固定模型。

月报页面负责月份、历史列表和分页；`useReports` 管理请求与任务生命周期；`ReportDetailPanel` 管理当前报告的删除确认和证据展开。详情组件以报告 ID 为 key，切换报告重置局部状态，刷新同一报告保留状态。

## 导入与离线恢复职责

statement_import 领域模块解析来源并保留全部源行分类依据，import_classification 在账户快照内统一去重和冲突。StatementImportService 结束预查询事务后解析，再锁用户重查 key、保存批次和流水。`api/errors.py` 统一全部接口的 `{detail: {code, message}}` 错误契约及 OpenAPI 响应模型；参数校验不回显原始输入，依赖不可用和内部异常不暴露 SQL 或异常原文。观测模块通过请求上下文与 SQLAlchemy 事件计时，不存储业务载荷。

数据库批次保存 idempotency_key、request_digest、parser_version 及完整计数，errors 仅保留有界明细；历史新增统计为 null。页面 importRecovery 负责最小配置持久化，useImportWorkflow 负责冻结输入、原 key 重试和结果展示。

CLI 的 database_backup 管理 pg_dump/pg_restore、清单和目标校验；restore_validation 管理只读数据证据和显式任务状态调整；schema_evidence 核对列定义、约束表达式与索引。它们不调用 create_app，不启动消费者或模型客户端。


来源识别由 domain/source_detection.detect_statement 一次读取返回来源、版本、表头、映射与账户币种；接口只转换响应，账户命名复用解析后的来源。前端 api 仅处理 HTTP，账本、关系与月报的文件保存统一由 shared/download 完成。导入 hook 保留操作 key 归属检查，待确认记录的存储/ref/state 通过单一入口同步。


## 导入数据契约

解析成功时，`total_rows = new_rows + duplicate_rows + skipped_rows + error_rows`，`valid_rows = new_rows + duplicate_rows`。错误行按原始行号去重计数，issue_count 记录问题总数；预览展示最多 20 个有效行，错误与排除详情各最多 100 条，截断不改变完整计数。金额使用 Decimal，并以字符串传输。

稳定交易编号在同一账户内去重：同编号同事实首行新增、其余重复；同编号事实不同整组拒绝。无编号记录以规范化事实及出现次数识别，保留同文件内两笔相同交易，但不保证不同导出范围中的相同事实属于同一交易。未知来源状态拒绝入账，已识别但结构不完整的来源不得回退为标准 CSV。

任何行错误产生 REJECTED 批次、实际写入为零，不创建新账户；new_rows 仍表示提交时可新增数量。全重复/全排除均新增零笔。撤销删除该批实际流水，保留批次及提交时计数。历史新增统计保持 null，不推算或伪装为零；结构不可解析直接返回 422，不制造零行批次。

正式导入必须携带幂等 UUID。同用户/key 唯一，同 key 不同摘要返回 409；同 key 重试返回原批次，包括已撤销状态。摘要覆盖规范化文件名、原样正文、完整映射、账户 ID/名称和币种，不包含当前解析版本。预览不锁定账本，正式提交重新检查账户和重复事实，以最终批次计数为准。

认证和幂等预查询结束后释放事务，再在线程中解析；新的写事务锁用户、重查 key，原子保存批次、账户、流水和修订号。预览在解析后使用可重复读事务读取账户与事实。提交成功后才返回，不依赖提交后再查询来组装结果。

待确认导入在 sessionStorage 只保存用户 ID、key、请求/文本摘要及冻结配置，不保存文件正文。存储失败阻止提交；认证暂时过期保留记录，主动退出或用户不匹配清理。刷新先查 key；404 不证明原事务已回滚，重新选择文件须匹配文本摘要，再以原配置和原 key 重试。所有异步结果按操作 key 或文件选择序号隔离，不能覆盖后续操作。

## 周期扣款与月度预算

规划契约和日期计算放在 `domain/planning.py`，规划查询与持久化集中在 `db/planning_repository.py`，助手提案读写放在 `db/assistant_repository.py`，`services/budgets.py` 编排预算证据与额度写入，`services/recurring.py` 编排周期配置与核对，共享排除和容量规则集中在 `services/planning_evidence.py`。接口只负责认证、月份范围、参数验证和事务提交；两个页面共用月份请求状态，逐期流水选择独立为组件。

预算以用户、月首、分类和币种唯一保存正数额度。实际支出不落冗余汇总表：在认证前建立可重复读快照，读取当月完整流水、确认关系及退款原消费，复用现有分类规则与用户修正。确认重复的副本、本人转账双边排除；已确认退款按到账月、原消费当前分类冲减，未确认正向流水不冲减。退款可导致月支出为负。原始分类汇总及月报仍保留原口径，不伪装为预算统计。

预算返回确定性金额和逐笔贡献，退款附原消费证据。修改分类、确认或撤销关系、撤销导入后，重新读取即反映当前账本。月度流水超过 10,000 笔直接拒绝，不用截断集合统计。复制上月只新增缺少的分类/币种额度，不覆盖当前月份，也不结转余额。

周期项保存账户、商户、币种、预期金额、月付/年付与首次日期；按首次日期推算每一期，短月份取月末，之后恢复原锚点。初始配置保存在主记录，财务与日期变更追加到 `recurring_revisions`，按查看月份选取生效配置；新增配置不能早于当前业务月份，且必须晚于上一版生效月及已核对期次所在月，不覆盖历史预期。从流水创建项目保留原流水日期作为周期起点，不将短月截断后的日期写回锚点。名称纠正只更新项目名称。编辑请求携带查看月份与项目版本，避免已有未来配置时，单独改名意外修改财务配置。当前状态为跟踪/暂停/结束：暂停仅隐藏未关联期次，恢复后重新按对应月份的配置展示；不保存暂停区间或推断暂停期间已免扣。结束不可恢复，已关联记录仍可查看和解除。

复制预算返回实际复制数与上月项数，区分无来源与全部已存在。净支出为正且未设置额度的分类/币种单独提示，复用同一账务证据。周期候选支持商户、日期和金额联合搜索，每页最多 10 笔；分页在完整读取的月度集合内进行，超过读取上限仍明确失败。周期编辑冲突保留输入，刷新后须显式确认最新版本。

每期最多关联一笔实际支出，每笔流水最多属于一期；允许用户跨月选择同账户、同币种流水，不要求商户文本和预计金额完全相同，金额不同明确提示。关联不改变交易关系或账本金额，不确认漏扣。撤销源流水通过外键解除关联；后续关系把流水排除后，页面标记需重核。预计扣款始终不进入预算实际支出。

写操作统一先锁用户并检查版本，旧版本不能覆盖新状态；预算同时校验记录身份，删除重建后旧表单失效；创建周期项使用客户端 UUID，重复相同请求返回原操作。预算月份、固定支出月份及账本期间在工作区 URL 中分别保存，切换月份、刷新及浏览器前进后退保持一致；页面保留挂载，通过月份和请求序号隔离响应；有草稿或写入时禁用月份控件，浏览器历史恢复保留草稿月份，旧写操作不能关闭新月份表单。浏览器请求按月份和序号隔离，写入失败保留表单。预算冲突刷新后展示最新额度，必须显式确认使用最新版本或重新建立，不能自动覆盖；周期页面刷新使跨月候选同时失效并重查，失效选项不可提交。所有页面金额来自服务端 Decimal；进度条只作比例展示。


用户明确确认的未发生期次保存在 `recurring_skips`，键为项目和预计日期；与实际匹配互斥，到期前不能确认，撤回不生成交易。未来配置修改/取消只能针对当前 UTC+08:00 月份之后且没有关联或未发生确认的区间；项目锁和版本检查复用现有写路径。

预算工作区在同一快照内返回分类支出和按币种覆盖范围，不另建汇总缓存。总览待办读取预算与固定支出工作区，任一读取失败独立显示；隐藏规划页的写入完成通过工作区回调通知待办重读。月报阅读摘要和 CSV 复用冻结快照；打印仅输出摘要，技术证据默认折叠，原始分类不改写为调整后统计。


总览期间通过 `overviewStart/overviewEnd` 独立保存，`start/end` 仅控制账本、关系核对与核查期间；显式下钻携带目标期间，普通导航保留筛选。预算和固定支出复用 `shared/DetailPanel` 的原生模态、Escape 与焦点恢复，草稿和面板显隐分离。周期列表筛选不卸载正在核对的详情，保存后状态变化仍能继续下一项。

预算覆盖按币种包含完整月度读取集合的流水数量与最近日期，来自同一查询快照，不能据此推断账单完整。下一计划日期遍历已安排配置的生效区间，复用月末/闰年日期规则；暂停和结束无下一期预测。总览关系候选按需读取，避免增加首屏扫描。人工配对规则单独位于 `pairEligibility.ts`，以整数分比较 Decimal 字符串，仅预筛当前快照；服务端保留最终关系事实、冲突与版本校验。月报提示和版本比较只读取保存的快照，不引入实时预算或分类数据。

## 对话助手（2026-09-16）

`domain/assistant.py` 定义严格的决策契约，`services/assistant.py` 执行最多 6 次模型决策的工具循环。每一步可读取一个月份的收支、预算或固定支出，直接回答、追问，或提出预算修改。请求总预算为 90 秒，Web 代理读取超时为 120 秒；模型等待期间不持有数据库连接，不使用关键词匹配、固定工作流或模型失败回退。

模型接收当前对话、参考月份及所选工具返回的数据；预算流水证据、固定支出候选集合和总览最近流水不发送。模型文本属于解释层，用户可以展开服务端统计核对，不能作为写入或成功的证明。历史核查快照流程仍独立保留。

`assistant_actions` 保存 15 分钟有效的预算提案、原额度、目标额度、目标预算 ID 与版本。确认接口只接受提案 ID，从已认证用户归属读取提案；提案行锁、既有规划服务用户锁和乐观版本校验共同保护写入。更新与冻结回执同事务提交；重复确认读取同一回执，取消后不可执行。恢复准备取消所有待确认提案。模型无法调用确认接口。

Web 全局侧栏保留当前页面上下文，答案、查询依据、确认差异分层展示。对话仅在当前工作区内存保存，最多 7 轮，刷新后清除；操作提案及回执保存在数据库。预算确认后刷新已打开的预算页面和总览提醒，保留编辑草稿。当前操作仅涵盖预算设置/修改，不支持关系修改、固定支出创建、外部提醒或银行操作。


## 事务与异常边界（2026-09-17）

接收调用方 `AsyncSession` 的业务写入服务只修改或 flush，不提交；预算、周期、关系、助手确认/取消由 HTTP 路由在成功响应前提交。自行创建事务的导入用例、助手提案及离线恢复负责自身事务，不能包进外部事务后提前提交。

规划页面只管理编辑会话、导航和列表；预算与周期编辑器持有字段、校验及版本确认状态。收起或跨页时编辑器保持挂载，成功或取消才释放草稿。周期账户读取随页面重新激活而刷新；加载、失败、空账户分别显示，读取失败保留已有列表与草稿，阻止使用未确认的账户状态保存，并提供重试。保存失败保留表单；写入已成功但重读失败明确告知“已保存”，避免用户误以为写入失败而重复操作。前端只接受结构化错误契约，由 `shared/apiErrors.ts` 处理通用状态，各业务按错误码补充处理建议，不按消息原文推断类型。助手区分认证过期、模型不可用、无效输出、超时和容量错误，保留输入，不伪造成功或空结果。

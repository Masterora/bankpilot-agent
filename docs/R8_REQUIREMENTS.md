# R8 账期核对与固定支出暂停历史

本轮范围为用户确认的两项功能：账期核对与月结、固定支出暂停历史。本地实现与定向验收见 [验收记录](R8_ACCEPTANCE.md)。预算基础额度／模板、完整月报比较、共享预算和外部提醒不在本轮范围。发布、真实模型及真实账单来源认证仍分别验收。

## 账期核对与月结

以账户 ID 和月首唯一保存用户声明，不将“已导入”视为银行账单完整。账本页提供独立月份入口，按账户列出笔数、最早／最近入账日和分币种原始入账／出账；读取不受下方搜索条件或分页影响，不将退款调整消费混入原始金额。

- 待核对：无声明或用户已重新打开。
- 已核对：用户明确确认已对照原账单核对，包含空月需自行确认的提示。
- 已月结：月份已结束且当前版本已核对，用户再次确认。
- 需重新核对：此前核对／月结使用的账本修订已过时；保留此前状态和确认时间供识别。

本轮沿用用户级 `ledger_revision` 保守失效：任何导入、撤销、分类、关系或账户名称等推进账本修订的写入，都使该用户已有声明失效，即使修改发生在其他账户或月份。避免新增一套漏维护的局部修订机制；后续精确失效须独立设计。

月结是工作流标记，不阻止补录、改类或关系核对，不承诺银行余额对账、来源认证或账单完整性。允许核对当前月，只有结束月可月结；未来月、非月首和不支持年份直接拒绝。读取超过同用户当月 10,000 笔时整体失败，不从部分数据确认。

写入先锁用户，校验账户归属、期望声明版本和期望账本修订；月结再次检查状态与业务日期。并发请求只允许一个使用同版本提交。结果不明时刷新查询当前状态，不自动换版本重做写入。读取只读，确认与重新打开不会推进账本修订。

## 固定支出暂停历史

按业务日记录状态生效边界。暂停后恢复构成区间；期次是否需要核对由预计日期当天的状态决定。今天暂停不会抹去之前有效的未核对期次，已关联和“本期未发生”记录继续保留。预计金额不会写入账本。

- 允许今天或未来生效，不允许追溯改写已过去的日粒度记录。
- 同一天以最后一次明确确认的状态为准；不宣称记录日内的每次暂停。
- 未来边界可经确认取消；同日期保存替换该日期边界，其他日期保留。
- 结束后不允许后续状态；已安排的未来结束可取消或在生效前替换，已经结束不可恢复。
- 安排结束不得悄悄删除其后的排程，须先显式取消冲突的未来变更。
- 所有写入仍校验用户归属与计划版本，失败或回滚不留部分边界。

旧计划从未保存过暂停区间，升级不能伪造历史。保留旧主记录状态作为未知历史的兼容基线，`status_known_from` 为空表示未知；首次变更开始记录可信历史。新计划从起始日期记录基线。页面显示历史起点、已安排边界、本期状态与当前状态。

共享期次投影、匹配／跳过校验、R5 待办与 R7 通知均按预计日期的状态读取。下一计划日期在配置与状态生效区间共同搜索，能跨过暂停找到未来恢复期次，保持月末／闰年锚点。发现的重复保护仍包含所有状态的计划，版本变化使旧发现令牌失效。

## 持久化与交付

迁移 `20261009_0022` 新增 `account_month_reviews`、`recurring_status_changes`，为计划增加 `status_known_from`；不改写发布迁移。结构版本同步为 0022，共 34 张业务表。两项数据纳入个人 JSON 导出、全库备份恢复和用户／账户级联清理。

验收需覆盖声明状态机、旧修订与并发拒绝、归属隔离、容量、只读与回滚；暂停／恢复边界、当前／历史状态区分、旧计划未知历史、终止规则、月末闰年；认证 API、实际页面中英文操作及窄屏布局；升级保留旧数据、隔离升降级、备份还原。静态检查单独记录，不替代以上行为验证。

目标环境迁移与前后端发布须另行授权；历史 0021 备份不直接兼容 0022 的严格恢复核对，须用对应版本应用恢复并按正式升级流程迁移。降级会丢失声明及暂停历史，不能用于带数据环境的盲目回退。

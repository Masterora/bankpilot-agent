# R4 同口径消费比较交付记录

日期：2026-09-21。实现基线：`main@173f62a` 加本轮变更。未推送或发布；无数据库迁移。

## 已实现

- 新增 `compare_spending` 严格工具。模型只识别双月和币种；服务端在一个可重复读快照内计算两期消费、退款、实际支出、覆盖和分类差额，形成终止型确定性结果。
- 当前月比较按业务日期同日截断，短月份取月末；过去月份使用完整自然月，未来目标月拒绝。
- 比较卡保存账本修订、`spending-v1` 和 `comparison-v1`。分类证据接口绑定当前用户的已完成轮次，只接受侧别、已保存分类和页码。
- 新增结构化“按当前日期重新比较”：复用原双月和币种，不调用模型，不修改已选择的消费或搜索范围。
- 助手协议硬切换到请求头/请求体版本 4、结果版本 3。旧请求不兼容；旧结果不返回正文、证据、提案，也不进入模型历史。
- Web 新增双月结果卡、覆盖警告、两侧分类证据、版本失效、专用重新比较、稳定分类键和 375px 纵向布局。

## 评审修复

- 比较卡按不可变结果分别记录本地账本变更计数，重新比较生成的新卡可正常打开两侧证据，旧卡继续失效。历史重读仍由服务端校验真实账本修订和计算版本。
- 不支持版本的待处理记录单独保存在按用户隔离的 `assistant-unverified` 存储中。发送新问题不覆盖它；用户可显式按原请求身份查回，查到并打开会话后清除，404、存储失败和迟到响应均保留身份。没有旧请求转换或重放。
- 比较证据接受已保存结果中的全部分类，包括负金额流水被用户改为 `income` 的情况；消费与退款金额规则保持不变。正收入仍不进入消费比较。
- 评审期间曾将前端源码正则检查替换为组件状态/事件测试，新增 PostgreSQL/HTTP 验收并配置 CI，修正恢复测试里仍期待旧结果正文可读的断言；这些测试及 CI 执行入口随后按要求删除。

以下为删除前的本地验证记录。2026-09-21 已按要求删除全部测试/验收脚本、配套数据与结果文件，以及 Makefile 和 CI 中的对应入口；下列测试命令不再可用。删除后的 `make verify`（静态检查与构建）及 `git diff --check` 均通过，不代表业务回归或真实模型验收通过。

- `make verify-comparison`：固定夹具独立断言消费差、退款差、净额差、分类并集、稳定排序、无数据/零值边界、合法负实际支出、闰年和当前月同日范围；协议 3 被拒绝。
- `make verify-interactions`：既有消费证据、会话恢复、迟到响应、退出隔离和上下文保存前端回归通过。
- `comparison-frontend.cjs`：账本变化只禁用旧卡、新卡两期入口正常、无数据无持平结论、分类证据分页/流水定位、隐藏后的迟到响应和服务端版本失效通过。
- `conversations-frontend.cjs`：升级前的请求身份跨新请求和刷新保留；显式核对不重放，失败保留、成功清理，切换会话后的迟到响应及归档存储失败均通过。
- 隔离 PostgreSQL 17：`make verify-business`、`make verify-conversations`、`make verify-search` 通过，包括真实备份/恢复及仅临时库的迁移往返。
- `make verify-comparison-db` 对应脚本通过：独立金额预期、跨月退款原消费改类、`income` 分类两侧证据、稳定分页、币种/用户隔离、双版本失效、协议头拒绝、零模型重新比较、请求幂等、上下文冲突、并发快照、删除竞争和容量边界。

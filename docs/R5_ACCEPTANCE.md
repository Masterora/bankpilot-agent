## 验证边界

### 进入 R6 决策切片前的补验清单

以下四项在最终 R5 代码状态上逐项复核；每项记录代码提交、数据库结构版本、隔离环境、用例输入、预期与实际结果。此前分散的定向检查可作准备证据，不自动等于本清单通过。任一项未通过或未执行，就标记为待补验，不宣称 R5 完整验收。

1. **容量与回滚**：在独立 PostgreSQL 中分别覆盖月度 10,000 和 10,001 笔流水的预算及固定支出待办读取、状态写入与事实变更；10,001 必须返回既定容量错误，不能显示不完整的零待办，也不得留下部分状态或回执。含跨月退款、关系变更与撤销导入的边界用例，核对事务回滚前后状态一致。
2. **事务竞争**：同一用户两个不同操作 ID 以相同期望版本并发写同一待办，最终只有一个状态变更，另一请求明确冲突；同 key 同载荷回放冻结结果，异载荷冲突。待办写入与来源事实修改并发时，最终状态与提交后的事实一致；强制中途失败后无半成品。偏好版本竞争同样验证，不以串行调用代替。
3. **恢复**：用当前结构版本在隔离库完成备份、还原和 `restore-check`，核对待办状态、偏好、操作回执及 unknown/稍后处理状态；恢复准备重复运行不丢失已确认结果、不产生重复有效操作。仅使用一次性数据库，不对共享业务库执行降级或恢复。
4. **浏览器闭环**：当前 Web 构建连接真实 API 与隔离 PostgreSQL，覆盖中文/英文、1440px/375px、键盘操作、刷新、切换账号、弱网响应丢失后原 key/原载荷重试，以及错误组恢复后计数纠正；确认旧月份响应不能覆盖新月份、未确认结果不会显示为成功，且移动端没有横向溢出。受控响应桩可辅助定位，但不能单独通过此项。

- 已收敛实现：认证连接与读取快照分离；待办写入由一个可恢复操作状态管理；助手及待办共用私网 HTTP 可用的 UUID 生成器；API 成功写入统一通知总览与规划页刷新。旧操作锁、重试 ref、助手修订计数和页面保存广播回调已移除。

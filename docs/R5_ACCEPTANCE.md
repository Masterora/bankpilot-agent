## 验证边界

### R5 完整补验清单

以下四项在最终 R5 代码状态上逐项复核；每项记录代码提交、数据库结构版本、隔离环境、用例输入、预期与实际结果。此前分散的定向检查可作准备证据，不自动等于本清单通过。任一项未通过或未执行，就标记为待补验，不宣称 R5 完整验收。

1. **容量与回滚**：在独立 PostgreSQL 中分别覆盖月度 10,000 和 10,001 笔流水的预算及固定支出待办读取、状态写入与事实变更；10,001 必须返回既定容量错误，不能显示不完整的零待办，也不得留下部分状态或回执。含跨月退款、关系变更与撤销导入的边界用例，核对事务回滚前后状态一致。
2. **事务竞争**：同一用户两个不同操作 ID 以相同期望版本并发写同一待办，最终只有一个状态变更，另一请求明确冲突；同 key 同载荷回放冻结结果，异载荷冲突。待办写入与来源事实修改并发时，最终状态与提交后的事实一致；强制中途失败后无半成品。偏好版本竞争同样验证，不以串行调用代替。
3. **恢复**：用当前结构版本在隔离库完成备份、还原和 `restore-check`，核对待办状态、偏好、操作回执及 unknown/稍后处理状态；恢复准备重复运行不丢失已确认结果、不产生重复有效操作。仅使用一次性数据库，不对共享业务库执行降级或恢复。
4. **浏览器闭环**：当前 Web 构建连接真实 API 与隔离 PostgreSQL，覆盖中文/英文、1440px/375px、键盘操作、刷新、切换账号、弱网响应丢失后原 key/原载荷重试，以及错误组恢复后计数纠正；确认旧月份响应不能覆盖新月份、未确认结果不会显示为成功，且移动端没有横向溢出。受控响应桩可辅助定位，但不能单独通过此项。

## 功能验收矩阵

以下为应满足的验收条件，不表示全部已通过；实际结果与缺项以前文记录为准。

功能必须满足：

- 两个用户看到并修改的待办完全隔离。
- 已读状态跨刷新和重新登录保持，且不修改任何预算、流水或固定支出事实。
- 稍后项目在到期前隐藏、到期后重新出现；旧 token 写入被拒绝。
- 类型关闭跨登录保持，重新开启后按原有效状态恢复当前仍成立的项目。
- 预算告警等级升级会重新未读；固定支出从已匹配变为需重核会重新未读。
- 删除后重建预算不继承旧状态；不同固定支出期次不串状态。
- 多标签页偏好冲突不会静默覆盖。
- 预算已读后，在没有 GET 的情况下依次降至阈值以下、再升回原等级，仍重新未读；固定支出从需重核变合格再失效也重新未读。普通名称修改不重开。
- 同一事实的两个标签页分别执行稍后和已读，只接受符合当前状态版本的操作；恢复未读之后重试旧成功请求只返回旧回执，不覆盖新状态。同 key 不同内容明确冲突。
- 业务事实更新与状态写入竞争时按用户锁串行处理；业务事务回滚时 generation、状态和回执均不得留下部分提交。
- 有已读待办的月份从 10,000 笔导入至 10,001 笔时，满足原业务约束的导入成功，相关状态原子进入 unknown，旧令牌被拒绝；超限期间分类修改不因提醒计算超限被阻断。无关状态不变，数据库故障仍完整回滚。

- 认证 ASGI 与实际数据库：上月 100、支出 40、本月 120 得到结转 60/最终 180；随后本月改为 121 的新预览得到最终 181。超支分类不结转；不同币种独立，缺少目标额度时以原额度为基础。跨月确认退款使上月净支出为 -30 时，100 的原额度最多结转 100。

- 账本修订或预算版本变化使旧确认返回 409；同步阶段注入异常后预算与回执全部回滚。两条不同操作身份同时确认，同月份仅一个 200、另一个 409；原成功身份重试返回相同回执，没有重复增加。
- 历史来源/目标额度后续手动变化不会修改冻结回执。金额上限拒绝；10,001 笔源月流水拒绝完整操作，额度与回执均不写。删除合成用户级联删除结转回执；个人导出包含本人回执。

# 后续路线

当前已实现能力和未验收边界见 [当前状态](CURRENT_STATE.md)，现行契约见 [架构](ARCHITECTURE.md)。本文件仅描述尚未交付的方向，不重复已完成阶段的实施过程。

## 发布前基础工作

- 认证真实脱敏的微信/支付宝导出样本，核对数量、金额、状态、币种、退款及排除原因；合成样本不能代替来源认证。
- 在现有[确定性回归](ACCEPTANCE.md#自动化)基础上，补齐待办容量与事务竞争、月报任务与数据库中断、恢复和浏览器交互的覆盖。
- 使用代表性数据验证备份恢复，明确保留策略；个人数据 JSON 导出和自助注销已本地实现，真实规模及备份保留安排仍需环境验证。恢复清理聊天历史仍须明确确认，不能改写备份本体。
- 验证前后端同批发布、协议拒绝及生产链路；不得用本地通过替代生产验收。
- 模型质量验证按 [模型验证与边界](MODEL_VALIDATION.md) 单独安排，真实模型调用需明确授权。

## 固定支出发现

现行契约见 [架构](ARCHITECTURE.md#固定支出候选发现)；以下是样本认证和扩展门槛。

在编码阈值最终值之前，收集经用户授权、脱敏且来源认证的真实账单窗口，人工标注候选组、实际同一月付项目、同商户多订阅、退款、缺月和已有计划。按用户/商户分割调参集与最终盲测集，不能让同一组交易跨集泄漏。盲测集至少包含 50 个真实月付组及 50 个非月付或易混淆组，覆盖至少两个来源格式，并记录不同账户、币种、商户和历史长度的分布；样本不足则不达到一般用户启用门槛。保留逐例判断、规则版本、脱敏证据 ID、失败原因与复核者；合成样本只证明控制流。

盲测前冻结可评估范围：12 个完整月内，账户和币种已知、商户可识别、同组至少 3 个不同月份存在扣款；不要求连续、金额稳定或同月只有一笔，这些必须由规则决定，不能从召回分母中事后排除。对该范围内所有人工标注的真实月付组计算召回率；“证据不足”“不明确”及被规则拒绝的真月付都计为漏报。样本覆盖率为该范围内真月付组数 / 盲测集全部真月付组数，反映首版规则在真实资料中可能服务的比例。

最终评估分别报告正确候选、误报、漏报、精确率、召回率、样本覆盖率、拒绝/不明确数量以及按来源和币种的分层结果。一般用户启用须同时满足：候选精确率至少 90%（分母为所有提出的候选）、上述固定范围内召回率至少 50%、样本覆盖率至少 60%，且确定性硬门槛全部通过。无候选时精确率不可计算，不能记 100%；任一分层样本不足须明确标为未认证，不用总体结果代替。报告样本量与置信区间，不把这些点估计称为总体准确率。阈值如需调整，只能在查看盲测结果前基于调参集修改并升规则版本；盲测后不以同一批样本反复调到通过。真实样本不足或任一门槛未达标时，规则和交互可以以受控方式完成合成验收，但默认不向一般用户开启自动发现，也不视为已达到发布门槛。

当前保守阈值和商户通用名称清单须基于独立标注样本校准并升规则版本；提案及回执的长期保留成本仍须容量验证。

年付识别、金额预测和自动确认另行评估，不与月付发现一起交付。

## 事件与通知

站内通知默认关闭，启用条件见[验收说明](ACCEPTANCE.md#功能验收)。

固定支出发现通过真实样本认证和启用门槛后，再接入候选事件。

只有站内待办确实被使用，且用户明确需要离站提醒时，才追加一个外部渠道。届时单独交付时区/安静时段、用户订阅、退订、重试与投递回执；默认消息不含敏感交易详情。不同时接入邮件、短信和多个 IM。

站内通知启用门槛：同一事件无重复有效待办，事务回滚不发通知，关闭后不再投递。补齐事件竞争、恢复准备与投递重试回归。

## 演进边界

继续复用现有确定性消费计算、证据版本、用户锁和幂等回执，不增加相互独立的金额算法。持久任务沿用 PostgreSQL 租约与领取令牌，未经测量不引入 Redis、队列或服务拆分。

下一步补齐待办、发现建项与站内通知的验收缺口，达到门槛后再受控启用站内通知。外部通知以明确渠道需求为进入条件。模型解释不能代替候选证据、金额计算、权限判断或用户确认。

公开多用户共享账本、银行直连、资金操作、投资推荐和原生移动应用不在当前路线内。

飞书和支付宝沙箱的真实平台联调仍待配置凭据与公开 HTTPS 回调，见 [接入说明](INTEGRATIONS.md)。

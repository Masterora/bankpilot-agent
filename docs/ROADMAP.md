# 产品路线图

## 目标结果

BankPilot 最终交付多账户账单归一化、证据化 Agent 查询、主动财务核查和可审计本地操作，不建设通用银行操作平台。

```mermaid
flowchart LR
    I[多银行账单] --> N[归一化账本]
    N --> A[受控 Agent]
    A --> Q[证据化核查]
    Q --> C[用户确认]
    C --> L[本地修正 / 提醒 / 报告]
    L --> E[审计记录]
```

## 交付顺序

| 顺序 | 用户闭环 | Agent 与工程门禁 |
| ---: | --- | --- |
| 1 | 上传账单 → 映射字段 → 校验 → 去重 → 导入报告 | 文件限制、原子批次、行级指纹、失败行说明和重复导入为零 |
| 2 | 导入多个账户 → 识别账户间转账 → 形成统一账本 | 多币种隔离、转账双边证据、不可确定项进入人工核查 |
| 3 | 输入财务目标 → Agent 生成计划 → 调用多个只读工具 → 返回证据 | 严格 Schema、工具预算、用户隔离、证据绑定和稳定错误语义 |
| 4 | 核查异常 → 查看规则与交易 → 保存分类修正 | 金额可复算、原始交易不可覆盖、修正立即重算 |
| 5 | 核查周期扣款和预算偏差 → 确认本地提醒或预算修改 | 可信度、幂等确认、时区边界、撤销路径和审计记录 |
| 6 | 完成月度核查 → 生成脱敏报告 | 报告可复算、固定格式、隐私检查和导出测试 |
| 7 | 全系统发布验收 | 关键任务完成率、安全测试、迁移、恢复和远程运行全部通过 |

## Agent 工具扩展

| 阶段 | 新增工具 | 类型 |
| --- | --- | --- |
| 当前 | `query_transactions` | 只读 |
| 账单归一化 | `get_import_report`、`list_accounts` | 只读 |
| 证据化核查 | `get_finance_summary`、`explain_anomaly` | 只读 |
| 主动核查 | `list_recurring_charges`、`get_budget_status` | 只读 |
| 本地操作 | `correct_category`、`set_local_reminder`、`update_budget` | 用户确认后写入本地状态 |
| 报告 | `get_report_summary`、`generate_report`、`query_audit_log` | 摘要只读；生成需确认 |

单次 Agent 运行可以调用多个只读工具。任何本地写操作必须生成确认请求；确认绑定用户、Run、工具、参数摘要和有效期，重复确认不得重复执行。

## 稳定架构边界

| 领域端口 | 当前实现 | 可替换方向 |
| --- | --- | --- |
| `ModelGateway` | OpenRouter | 其他支持结构化输出的模型供应商 |
| 账单解析器 | 待实现 | 按银行和文件格式加载适配器 |
| 身份解析 | 本地 Session | OIDC、企业 SSO |
| 持久化 | PostgreSQL | 仅在业务收益明确时调整 |
| 通知 | 待实现 | Web、邮件或其他本地通知渠道 |
| 事件发布 | SSE | 多实例事件基础设施 |

框架不进入领域模型。权限、金额、归一化、去重、转账匹配、确认和幂等由应用与领域代码控制，不由模型决定。

## 发布门禁

| 指标 | 要求 |
| --- | ---: |
| 导入字段映射正确率 | ≥99% |
| 重复导入交易 | 0 |
| 金额可复算率 | 100% |
| 分析结论证据绑定率 | 100% |
| 原始账单发送给模型 | 0 |
| 提示词注入成功调用越权工具 | 0 |
| 未确认本地写操作 | 0 |
| 跨用户数据访问 | 0 |
| 关键任务完成率 | ≥95% |
| API、Web、迁移、恢复和远程健康检查 | 全部通过 |

## 范围外能力

真实转账、收款、卡片状态变更、代扣关闭、理财交易、非公开银行接口、MCP、Temporal 和消息队列不属于当前产品范围。新组件仅在已有闭环出现明确容量或可靠性需求时引入。

# 产品路线图与迭代任务

## 产品目标

将普通用户可获取的账单转为可验证的流水与交易关系，通过证据核查减少重复统计和人工核对。系统不执行银行操作，不以模型生成的解释替代财务事实。

## 当前任务：已实现功能闭环

| 编号 | 任务 | 状态 | 验收依据 |
| --- | --- | --- | --- |
| C01 | 拒绝歧义金额，保留时间精度 | 完成 | 逗号金额拒绝；日期或未知精度不触发分钟级规则 |
| C02 | 导入预览、编号冲突、批次撤销与重导 | 完成 | 固定 CSV 接口验收；预览零写入、错误整批拒绝 |
| C03 | 来源详情、分类保存、账户与商户筛选、CSV 导出 | 完成 | 接口与组件测试；导出保留金额并防止文本公式执行 |
| C04 | 异常待处理、正常、待核实、备注及恢复 | 完成 | 刷新恢复、跨用户拒绝、撤销后证据失效 |
| C05 | 历史运行入口与不可覆盖的结果快照 | 完成 | 最近 50 条用户历史；分类变化通过新查询体现 |
| C06 | 本地质量检查 | 完成 | API、Web、静态检查与构建，见交付状态 |
| C07 | PostgreSQL 迁移与远端页面验收 | 待验证 | 隔离 PostgreSQL 迁移、远端接口及真实浏览器 |
| C08 | 机构原生账单验收 | 待样本 | 普通个人用户实际导出的脱敏文件；禁止用虚构 CSV 替代 |

完成指本地实现与对应自动化验证，不代表生产发布。当前代码仅表达流水口径，不计算抵销转账与退款后的净消费。

## 后续交付顺序

| 顺序 | 用户闭环 | 实现任务 | 验收条件 |
| --- | --- | --- | --- |
| 1 | 取得原账单 → 无需改表导入 | 选择两个可获取来源；版本化解析器、状态与方向、来源账户绑定、错误恢复 | 两个真实脱敏来源；数量、日期、金额逐项核对；错误不静默放行 |
| 2 | 多份记录 → 可信交易关系 | 稳定账户身份、来源编号命名空间、重复/转账/退款候选、确认和撤销 | 原记录保留；误合并测试；证据不足保持待核实 |
| 3 | 核查任务 → 必要追问 → 确认重算 | Agent 检查覆盖、选择只读工具、寻找证据、请求有限确认 | 权限与金额由程序控制；结果有据，不能判定时停止结论 |
| 4 | 月度核查 → 差异报告 | 数据版本、规则版本、未决问题、流入流出与净消费分栏、可复算导出 | 固定输入重现结果；新数据产生新报告，不覆盖旧报告 |
| 5 | 持续使用 → 发布验收 | 用户验证、恢复与删除、备份恢复、隐私告知、性能与分页 | 普通用户完整完成任务；隔离、迁移、恢复、线上验证通过 |

周期扣款、预算与通知延后至交易关系和期间覆盖可靠后；保留的界面空态不是已交付能力。

## 稳定架构边界

| 边界 | 职责 |
| --- | --- |
| 来源适配器 | 文件结构、精度、状态与来源身份；不猜测机构语义 |
| 标准交易 | 不可覆盖的标准化流水与来源指针 |
| 交易关系 | 重复、转账、退款关联及用户确认；不等于交易分类 |
| 核查结论 | 对规则证据的用户判断，不修改金额或代表银行处理 |
| 报告与运行 | 数据范围、版本、规则与结果快照 |
| Agent | 模型选择步骤；程序执行授权、计算和证据校验 |

当前以 PostgreSQL 和既有应用分层实现。只为正在交付的闭环建立模型，不提前创建空服务或新增基础设施。

## 质量与效果门禁

| 指标 | 通过条件 |
| --- | --- |
| 金额 | 已支持格式零静默改值；小数语义不明确则拒绝 |
| 去重 | 固定验收集重复导入新增为零；不同真实交易不误合并 |
| 证据 | 不以补零时间证明分钟间隔；不以交易首末日证明期间完整 |
| 用户隔离 | 越权读取、写入、核查与历史访问均拒绝 |
| 结果 | 固定数据和规则可复算；快照不被分类修正覆盖 |
| 模型 | 不自动发送原文件；用户输入仍会发送至配置的模型供应商 |
| 任务效果 | 对照同样数据的人工核对，记录用时、确认次数与错误；减少一半用时为待验证目标 |
| 发布 | API/Web、隔离 PostgreSQL 迁移、恢复与真实浏览器验收通过 |

## 范围外

真实转账、收款、银行卡状态变更、代扣关闭、理财交易、非公开银行接口。核查不保证发现所有异常，也不推导实时余额或已发生退款。

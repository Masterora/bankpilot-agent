# 产品路线图

产品围绕一条使用路径演进：用户导入账单，核对关系，查看有证据的分析，再获得可复算的周期报告。每次交付都应让这条路径更完整。

## 当前交付：Agent 关系证据

将关系工作区已经确认的重复、本人转账和退款纳入 Agent 查询，同时保留原始统计。结果带有关系状态、双方交易和来源信息，并保存读取时的快照。

完成标准是同一份输入产生一致金额，未确认候选不调整金额，跨期关系可以解释，历史结果不随当前账本变化，数据覆盖未认证时不声称完整。

## 下一交付：可复算的月度报告

报告采用不可变快照，重新生成创建新报告，不覆盖旧证据。用户账本修订号在新增流水、撤销批次、分类修改及关系状态变化的同一事务递增；报告保存修订号与计算规则版本。版本不同即标记“账本已更新”，不自动重算。首版采用用户级修订号，允许无关月份变动触发保守提示，不宣称报告金额一定变化。

报告直接复用确定性核查端口，不依赖模型规划。生成请求使用幂等键；后台执行采用原子领取的持久任务、有限重试与用户并发额度。现有进程内 Agent 查询不承担周期调度。

撤销导入不删除历史证据；用户主动删除报告或注销并清除数据时，应清理对应快照。普通页面不提供修改历史快照的能力。以上为报告交付契约，不代表相关服务已实现。

在已有快照上形成可保存、查看与导出的月度报告。报告固定统计月份、币种、关系口径和生成时间；账本变化后重新生成报告，用户可以识别报告是否需要更新。

报告必须同时展示原始与调整统计、待核对事项和数据范围。不把来源缺口解释为零消费，不把调整净额当作银行余额。完成标准是从报告返回证据后，能够复算每项金额。

## 持续推进：真实来源与运行可靠性

来源认证可与功能开发并行，但“某来源已认证”的结论必须来自实际导出文件。获得脱敏样本后，逐一核对导出入口、表头、交易数量、金额、时间、状态和退款语义；公开格式说明与合成样本不能代替这一证据。

运行可靠性持续覆盖迁移、备份恢复、用户隔离和页面验收。业务回归是否进入 CI 需要明确的维护范围，不能以静态检查代替。

## 后续能力：周期扣款与预算

两项能力的入口继续保留。实现前先解决识别依据和用户校正：周期扣款支持确认与排除，预算支持额度、币种与统计口径设置。提醒应能关闭，并能追溯触发原因。

这些能力只分析已导入账单，不自动关闭代扣、不转账，也不承诺实时提醒。

## 架构约束

来源适配器解释文件，领域规则计算金额，关系记录表达用户确认，Agent 选择受限工具，快照保存结果证据。新能力复用这些职责；未经确认的数据不能悄悄变成确定结论。
